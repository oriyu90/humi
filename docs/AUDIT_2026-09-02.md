## A. メモリ安全性・ライフサイクル

| # | 事項 | 深刻度 | 判定 |
|---|---|---|---|
| A1 | **`NotesArchive.runDitto` のパイプがデッドロックしうる。** `proc.standardOutput = Pipe()` を作るが**一度も読まない**。`standardError` も `proc.waitUntilExit()` の**後**に `readDataToEndOfFile()` するだけ。`ditto` が stdout/stderr に OS パイプバッファ（≈64 KB）を超えて書くと、`ditto` が write でブロック → `waitUntilExit()` で無限待ち。`GitStatus` と違い**タイムアウトのバックストップが無い**。通常の `ditto -c/-x` は出力が僅少なので実害は稀だが、ユーザー操作（メモの ZIP 入出力）で踏む経路。 | 中 | **[fix]** `standardOutput = FileHandle.nullDevice`、stderr は `readabilityHandler` かバックグラウンドキューで先に吸うか、`ditto` に短いタイムアウト（`terminate()`）を付ける |
| A2 | **`StatusBarClock` の subscribe/unsubscribe が `.onAppear`/`.onDisappear` 対に依存。** 親が急に消える等で `.onDisappear` が発火しないと `subscribers` が減らず、12s タイマーが止まらない（プロセス寿命リーク）。1 本・12s なのでコストは無視できるが「アイドルで回り続けるものを足さない」方針に反する。 | 低 | **[fix]** `StatusBarView` に `.id` を与えて再生成境界を明確化する／または `subscribers` を `Set<ObjectIdentifier>` にして冪等化 |
| A3 | `ThemeStore.appearanceObserver`（`DistributedNotificationCenter.addObserver`）と `HotKeyCenter` の `InstallEventHandler` を解除しない。どちらもプロセス寿命のシングルトンなので実害なし。テスト分離や将来の複数ウィンドウ化に備えるなら `deinit` を用意しておくと安全。 | 低 | **[note]** |
| A4 | `NotesStore` は pre-1.4 の `notes.md` を読み込むが**削除しない**。移行後は使われないファイルが残るだけ（無害）。 | 低 | **[note]**（消すなら「移行済みマーカー」を書いてから） |
| A5 | `TitleTextHider`（`RootView`、`updateNSView` ごとに `window.titleVisibility = .hidden` を再適用）は v1.4.2 の `.windowStyle(.hiddenTitleBar)` 追加で**冗長**。害はないが `RootView` 冒頭のコメントは旧方式の説明のまま（stale）。 | 低 | **[fix]** `TitleTextHider` を削除し `.hiddenTitleBar` 一本化。コメントを現状に合わせる（回帰確認: sheet / `.fileImporter` 往復で「Humi」二重表示が出ないこと） |

## B. 安定性・正しさ

| # | 事項 | 深刻度 | 判定 |
|---|---|---|---|
| B1 | **`PaneTreeView.onPaneAreaSize` がリサイズのたびに `RootView.@State paneAreaSize` を書く。** ウィンドウリサイズ中は毎フレーム `RootView.body` 再評価が走る（`paneAreaSize` は `+` 押下時にしか使わない）。実害は体感しづらいが不要な再描画。 | 低 | **[fix]** `paneAreaSize` を `@State` に持たず、`+` 実行時に `NSApp.keyWindow` とサイドバー可視状態から算出するか、`onPaneAreaSize` を `.onChange` でデバウンス |
| B2 | **`NotesArchive` のインポート失敗がユーザーに伝わらない。** 失敗時は `NSSound.beep()` + `NSLog` のみ。「Humi のメモ ZIP ではない」「壊れている」等の理由が分からない。 | 低 | **[fix]** インポート失敗時にホームタブ上へ簡単なエラー表示（`.alert` か赤テキスト 1 行、`L(...)` 5 言語） |
| B3 | **`+` シートの主ボタンに `.keyboardShortcut(.defaultAction)` が無い。** Esc（キャンセル）はあるが Return で「そのまま開く／このフォルダで開く」を確定できない。 | 低 | **[fix]** 主ボタンに `.keyboardShortcut(.defaultAction)` |
| B4 | **アプリ内言語オーバーライドは標準メニューに即時反映されない。** v1.4.4 で `CFBundleLocalizations` を宣言し、`Localization.apply` が `AppleLanguages` を UserDefaults へ書くため**次回起動で**メニューバー・システムダイアログも追従するが、その場では英語のまま（アプリ内 UI は `L()` で即時）。 | 低 | **[fix]** 設定 › 一般 の言語ピッカー下に「メニューバーは再起動後に反映」の注記（`L(...)`）。任意で「今すぐ再起動」ボタン（`NSApp` 再起動ヘルパ） |
| B5 | **`NotesMarkdownPreview` のスクロール位置復元はブロック単位（≈段落粒度）。** v1.4.3 で `NSHostingView` 経由のピクセル方式（コードブロックを潰すバグの原因）を撤去し、`ScrollViewReader` + ブロック `.id` に置換したための粒度低下。「だいたい同じ位置」は満たすが、v1.4.0 のピクセル精度よりは粗い。復元失敗時は先頭表示（表示欠落は起きない）。 | 低 | **[later]** 各ブロックの実オフセットを preference で集め、目標フラクションに最も近いブロックへ寄せた後、そのブロック内の残差だけ `scrollTo` 後に微調整（安定性を最優先で慎重に） |
| B6 | **`MarkdownBlocks.blocks` は `body` 評価のたびに全文を再パース**（行ごとの正規表現）。`NotesMarkdownPreview` はスクロール中も `scrollFraction` 書き込み経由で再評価が増える。スクラッチメモの規模（数十〜数百行）では実測問題なしだが、パース結果を `text` をキーにメモ化すると綺麗。 | 低 | **[later]** `MarkdownBlocks` にパース結果キャッシュ（`@State` or 静的 LRU） |
| B7 | `PreviewMetricsKey.reduce` は `if n != M() { value = n }`（「最後の非デフォルト値を採用」）。emitter が 1 つなので現状は正しいが、将来 preference emitter が増えると脆い。 | 低 | **[note]**（emitter を増やさない前提を守る／増やすなら明示的な合成に） |
| B8 | `appendAxis` は `paneAreaSize == .zero`（`GeometryReader` 初回報告前に高速 `⌘N⌘N`）で `.horizontal` にフォールバック。稀だが「意図と違う向き」になりうる。 | 低 | **[note]**（B1 で `NSApp.keyWindow` 直読みにすれば自然に解消） |
