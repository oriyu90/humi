## A. メモリ安全性・ライフサイクル

| # | 事項 | 深刻度 | 判定 |
|---|---|---|---|
| A1 | **`DividerHandle` の `NSCursor.push()/pop()` 不均衡。** `.onHover { inside ? push() : pop() }`。ホバー中にペインが閉じてツリーが再構成されると `ForEach` の identity が変わり View が消滅、対の `pop()` が呼ばれず**カーソルスタックがリーク**（リサイズカーソルがシステム全体で固着しうる）。SwiftUI の `.onHover` は消滅時に `false` を保証しない。 | 中 | **[fix]** H5 で `NSTrackingArea` ベースの `cursorRect` 実装へ置換 |
| A2 | **タイルを閉じた直後に ⌘Q すると孤児シェスが残りうる。** `TerminalController.terminate()` は SIGTERM 後、SIGKILL バックストップ + `waitpid` を **1.5s 後の `DispatchQueue.global()`** に遅延。⌘Q が 1.5s 以内に来ると `applicationWillTerminate → terminateAllSync()` は `controllers`（既に当該を削除済み）しか回さないため、遅延ブロックが実行されず SIGTERM を無視する子が launchd へ再ペアレントされて残留。配置復元（`store.load`）でも同じ。 | 中 | **[fix]** S2: `TerminalRegistry` が「reap 保留 pid」を保持、`terminateAllSync()` がそれも SIGKILL + reap |
| A3 | `HotKeyCenter` の `InstallEventHandler` ハンドラを解除しない。プロセス寿命のシングルトンなので実害なし。 | 低 | **[note]** |
| A4 | `StatusBarView` が可視タイルごとに `Timer.publish(every: 12).autoconnect()` を持つ。v1.2 で多ペインが容易になり、タイマー数・`git` サブプロセス数が線形に増える。v1.1 実測はアイドル 0.0% だが将来的に共有タイマー化が望ましい。 | 低 | **[fix]** S4 の一部（共有タイマー） |

## B. 安定性・正しさ

| # | 事項 | 深刻度 | 判定 |
|---|---|---|---|
| B1 | **`handleOutput` が pty チャンクごとにメインアクタで重い処理。** `String(decoding: slice, as: UTF8.self)` + `components(separatedBy:)` + 行ごと `NSRegularExpression.firstMatch` + `localizedCaseInsensitiveContains`。トリガー有効時に `yes` 等の高速出力で UI がカクつきうる。加えて **チャンク境界で分断されたマルチバイト文字**が U+FFFD 化され、マッチ対象行が壊れる。 | 中 | **[fix]** S3: バイト境界をまたぐ UTF-8 をバイトバッファで持ち越し、1 チャンクあたりの行数・行長に上限、空パターン時は即 return |
| B2 | **`OutputMonitor.ingest` は完了行数に上限が無い。** 10 万行の貼り付け → 1 回の同期呼び出しでメインアクタ上に 10 万回の正規表現評価。 | 中 | **[fix]** S3 で 1 呼び出しの処理行数を上限化（超過分はドロップして計数だけ） |
| B3 | `PaneNode.normalized()` の 0 子 split フォールバックが `.leaf(UUID())`。現状は公開 API から到達不能だが、到達した場合セッション不在の葉を作る（`reconcile` が刈るので自己修復はする）。 | 低 | **[fix]** S10: フォールバックを「最初の子を返す / それも無ければ呼び出し側が nil 扱いできる形」に変更 |
| B4 | **`KeymapStore.installLocalMonitor` が first responder を問わずイベントを消費。** 再割り当てしたチョードは、設定ウィンドウのテキストフィールドやメモ欄編集中でも横取りされる（ローカルモニタは focus に関係なく発火）。別ウィンドウがキーでも発火。 | 中 | **[fix]** S5: キーウィンドウがメインウィンドウで、first responder がテキスト入力系でないときだけ消費 |
| B5 | `RootView.focusPane` は「現在フォーカス中のペイン」が確定しないと何もしない。2 ペイン以上で起動直後（クリック前）は `focusedController()` が nil を返すため `⌘⌃→` が無反応。 | 低 | **[fix]** S7: フォーカス未確定時は最初の葉を起点にする |
| B6 | `hasLiveForegroundChild` が `KERN_PROC_ALL`（全プロセス列挙 + 全件コピー）をメインアクタで実行。`closeNeedsConfirmation`（⌘W）だけでなく `StatusBarView.foregroundProcess` が **12s ごと・タイルごと**に呼ぶ（`statusProcess` ON 時）。 | 中 | **[fix]** S4: `KERN_PROC_PGRP` に絞る or 短期キャッシュ + status バーの tick からは外す |
| B7 | `GitStatus.git` のサブプロセスにタイムアウトが無い。ハングした `git`（ネットワーク FS・ロック）が actor を無期限ブロックし、同 dir の全タイルの `refreshGit()` が待たされる。 | 低中 | **[fix]** S6: `waitUntilExit` に上限（別スレッド + `Process.terminate()`） |
| B8 | `PaneTreeView.canvas` の `ScrollViewReader` に `ScrollView` が無く、`proxy.scrollTo(id)` は no-op。絶対配置なので実害は無いが無駄なラッパ。 | 低 | **[fix]** S9: `ScrollViewReader` 除去（または本物のスクロールに） |
| B9 | `.login` シェルの実体が fish の場合、OSC 7 スニペットは `osc7Snippet(.login)` = zsh 版が fish に送られてエラー。fish 対応で顕在化。 | 低 | **[fix]** S8: `.login` のとき `$SHELL` の basename で fish を判定してスニペットを選ぶ |
| B10 | 配置復元は `maximizedID` を保存・復元しない。 | 低 | **[note]** 許容（復元後は非最大化） |
| B11 | 不正な `.humiarrangement` を import すると、layout に無い `LeafSpec` から余分なペインが生える（`reconcile` が末尾へ追加）。 | 低 | **[fix]** S10 の一部: `materialize` で layout に無い spec は捨てる |

## D. GUI / Hallmark 精査

Hallmark 契約（社内ドキュメント準拠）: 8 インタラクション状態（default / hover / keyboard focus / pressed / disabled / loading / error / success）を区別、可視コントロールは十分な当たり判定、**フォーカスリングは 3pt 以上の高コントラストで常時識別可能**、primary は塗り + 暗色文字、**状態は色だけでなくテキスト/アイコンでも伝える**、light/dark 両方のコントラストを検証、フル キーボード操作（Tab / Shift+Tab / Enter / Space / Esc）。

| # | 事項 | 判定 |
|---|---|---|
| D1 | **`HumButtonStyle` に hover / keyboard-focus / loading / error / success が無い。** `makeBody` は `configuration.isPressed` と `isEnabled` しか見ておらず、コメントの「lift on hover」も実装されていない。Hallmark の 8 状態のうち 3 つ（default/pressed/disabled）しか無い。**最大の GUI ギャップ。** | **[fix]** H1 |
| D2 | `Hum.focusRing`（0x2E93C6）が定義済みだが**どこにも使われていない**。カスタムコントロールにフォーカスリングが一切無い。 | **[fix]** H1/H2 |
| D3 | ペインのフォーカスリングは `accent.edge` の 2pt。(a) キーボード/Tab フォーカスに追従しない（`.humiFocusChanged` は `mouseDown` からのみ）。(b) 起動直後の最初のペインはリング無し。(c) accent 色（中彩度）は暗テーマで一部コントラスト不足。Hallmark は「専用の高コントラスト指標」を要求。 | **[fix]** H4 |
| D4 | `TerminalTileView.tileButton`（閉じる/最大化/再起動）が 22×22pt。hover 背景も focus リングも無い（`.buttonStyle(.plain)`）。 | **[fix]** H3 |
| D5 | `DividerHandle` の可視ルールが `Hum.hairline`（不透明度 10–12%）でほぼ見えない。hover 強調も無い。キーボードでの比率変更手段が無い（マウス専用）。 | **[fix]** H5 |
| D6 | `AlertsPane` のトリガー行: アイコンのみの trash ボタンに `accessibilityLabel` 無し、`Toggle("", …)` にラベル無し、最小サイズ指定無し。 | **[fix]** H6 |
| D7 | `Increase Contrast`（`accessibilityDisplayShouldIncreaseContrast`）非対応。hairline 10% / tint 6–12% は増強すべき。 | **[fix]** H7 |
| D8 | コントラストの自動試験がテストスイートに無い。 | **[fix]** H8 |
| D9 | トリガー `.color` の発火合図がタイル色変化のみ（色だけ）。git dirty は塗り丸 vs 不在なので境界的に許容。 | **[note]** H6 のラベル付けで補足 |
| D10 | `Motion.considerate` は Reduce Motion のみ対応。Reduce Transparency は未対応。 | **[note]** H7 に含める |
