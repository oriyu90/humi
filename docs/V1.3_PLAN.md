## Track 1 — 安定性・メモリ安全性・確実性

### S1. `TerminalRegistry` の reap 保留リスト（AUDIT A2）
- `terminate(_:)` / `terminateAll()` で `controllers` から外す前に、pid を `pendingReap: [(pid: pid_t, since: Date)]` へ積む。
- `TerminalController.terminate()` の遅延ブロックが reap に成功したら `TerminalRegistry.noteReaped(pid)` で消す。
- `terminateAllSync()` の最後に `pendingReap` を走査 → まだ生きていれば SIGKILL + `waitpid`。
- `pendingReap` は 5s TTL で剪定（`terminate()` の遅延は 1.5s + 0.3s なので十分）。
- テスト: `pendingReap` の積み/消しのユニット（pid は擬似値でよい。実プロセスは張らない）。

### S2. `hasLiveForegroundChild` を軽く + status バーから外す（AUDIT B6, A4）
- `sysctl` を `KERN_PROC_PGRP`（プロセスグループ）に絞る。取得できない環境では従来の `KERN_PROC_ALL` にフォールバック。
- `TerminalController` に 1.5s TTL のキャッシュ（`closeNeedsConfirmation` の連打対策）。
- `StatusBarView.foregroundProcess` は「実行中インジケータ」を **タイマー tick では評価しない**（cwd 変化時のみ、または廃止）。まずは廃止候補（`statusProcess` は既定 off、値はプレースホルダ `…` のみ）。→ **`statusProcess` UI は残すが、判定を `hasLiveForegroundChild` の TTL キャッシュ経由にして tick からの呼び出しを止める。**
- 共有タイマー: `StatusBarClock`（`ObservableObject`, 1 個の `Timer`）を作り全 `StatusBarView` が購読。
- テスト: PGRP 版が PID 版と同じ bool を返すこと（自プロセスで検証）。

### S3. 出力監視のフラッド耐性 + UTF-8 境界（AUDIT B1, B2）
- `OutputMonitor` をバイトベースへ: `ingest(_ bytes: ArraySlice<UInt8>) -> [String]`。未確定バイト列（改行までの末尾）を `[UInt8]` で保持し、**行が確定してから** `String(decoding:as:UTF8.self)`。マルチバイトの分断が起きない。
- 1 回の `ingest` が返す行数を `maxLinesPerIngest`（例 200）で打ち切り、超過分は捨てて `droppedLines` を積算（次リリースのデバッグ用ログのみ、UI には出さない）。
- 1 行の長さを `maxLineLength`（例 4096）で切り詰めてからマッチ。
- `handleOutput`: `watchStrings` も `triggerEngine` も空なら `onOutput` を張らない現行動作は維持（`refreshAlertWatchers`）。張っている場合でも、空行・打ち切り行は `matches` に渡さない。
- テスト: 分割された 3 バイト文字（"あ" = E3 81 82）をバイト 2+1 で分けて ingest → 復元されること。大量改行 → 返り行数が上限で頭打ち。行長の切り詰め。

### S4. `KeymapStore.installLocalMonitor` を安全化（AUDIT B4）
- モニタ内で消費する条件を追加:
  - `NSApp.keyWindow` がメインウィンドウ（`identifier == "humi-main"` 相当。`Window(id:)` の frame 判定でなく `NSApp.mainWindow` と一致でよい）。
  - `keyWindow.firstResponder` が `NSText` / `NSTextView` / フィールドエディタでない（テキスト入力中はスルー）。
- 上記を満たさなければ `return event`（従来経路へ素通し）。
- テスト: 純粋関数 `KeymapStore.shouldConsume(chord:isMainWindowKey:responderIsTextInput:)` に切り出してユニット。

### S5. `focusPane` のフォールバック（AUDIT B5）
- `RootView.focusPane`: 現在フォーカスが取れないときは `store.layout?.leaves().first` を起点にして `paneNeighbor` を呼ぶ。
- それも無ければ何もしない（従来どおり）。

### S6. `GitStatus` のサブプロセスタイムアウト（AUDIT B7）
- `git(_:)` に `timeout: TimeInterval = 2.0`。別スレッドで `p.waitUntilExit()` を待ち、超過で `p.terminate()` → `nil`。
- `actor` 内なので 1 dir ずつ直列。タイムアウトで打ち切れば他 dir の詰まりは解ける。
- テスト: `/bin/sleep 5` を食わせて ~2s で nil が返る（`GitStatus.run` にテスト用フックを足すか、`git` パスを差し替え可能に）。

### S7. `PaneNode.normalized()` の空 split（AUDIT B3, B11）
- 0 子 split は「最初の子」を返す（1 子と同じ畳み）。子が本当に空なら…**そもそも `.split` は最低 2 子で構築される**ので、`normalized` の入口で `children.isEmpty` は `precondition` ではなく「呼び出し側が nil を期待する」ケースにのみ発生。現行の `remove` は 0 子で先に `nil` を返すので `normalized` に空 split は来ない。→ **フォールバックを `.leaf(UUID())` から「`children.first?.normalized() ?? self`」に変更**し、`self`（空 split）が返る余地は `Codable` の throw で塞がっているのでコメントを正す。
- `ArrangementStore.materialize`: `layout.leaves()` のうち `LeafSpec` に無い id は今も prune 済み。逆に **`LeafSpec` にあるが layout に無い id は Session を作らない**（現行は作って `reconcile` が末尾追加していた）。→ layout に出現する id の spec だけ Session 化。
- テスト: materialize で余分 spec が無視されること。

### S8. `.login` シェルが fish のときの OSC 7（AUDIT B9）
- `TerminalRegistry.controller(for:)` の `shellKind` 決定を: `.login` のとき `ProcessInfo` の `$SHELL` basename が `fish` なら `.fish` として `osc7Snippet` を選ぶ（`ShellResolver` に `effectiveKindForOSC7(config:environment:)` を新設、純粋関数）。
- テスト: `effectiveKindForOSC7(.login, ["SHELL":"/opt/homebrew/bin/fish"]) == .fish` など。

### S9. `PaneTreeView` の `ScrollViewReader` 除去（AUDIT B8）
- `ScrollViewReader` と `proxy.scrollTo` を削除。`onChange(of: store.lastAddedID)` は `focusedID = id` の更新だけ残す（新規ペインにフォーカスリングを付ける＝ H4 と整合）。

## Track 2 — Hallmark GUI

### H1. `HumButtonStyle` を 8 状態対応に（AUDIT D1, D2）
- `Kind` はそのまま（push / soft / outline）。`status: HumStatus`（`.idle / .loading / .success / .error`）を追加。
- `makeBody` に:
  - **hover**: `@State private var hovering`（`.onHover`）で push の lift（y オフセット・影を hover 時に増やす）。
  - **keyboard focus**: `@FocusState` は ButtonStyle 内で使えないため、`.focusable()` + `FocusState` をラッパ `HumButton` View に持たせるか、`ButtonStyle` は `@Environment(\.isFocused)`（mactrue 14+ で `Button` に効く）を読む。→ まず `@Environment(\.isFocused)` を試し、不可なら薄いラッパ `HumButton(role:action:label:)` を新設して置換。
  - focus 時: `Hum.focusRing` の 3pt ストロークを pill の外側に。`accessibilityDisplayShouldIncreaseContrast` で 4pt。
  - **loading**: ラベルを `ProgressView().controlSize(.small)` + テキストに、`disabled` 相当（押下不可）。
  - **success / error**: 先頭に SF Symbol（`checkmark` / `exclamationmark.triangle`）+ 縁色を mint / coral に。**色だけに頼らずアイコンを付ける。**
- `.hum(...)` ヘルパに `status:` を追加（既定 `.idle` で後方互換）。
- テスト: 状態→色/オフセットのマッピングを純粋関数 `HumButtonStyle.resolve(kind:status:pressed:hovering:focused:)` に切り出してユニット。

### H2. 再利用フォーカスリング modifier（AUDIT D2）
- `View.humFocusRing(_ show: Bool)` → `overlay(RoundedRectangle(...).stroke(Hum.focusRing, lineWidth: contrast ? 4 : 3))`。角丸は環境から（`.hum` の pill / tile / input）。
- `KeyRecorder` / `ColorWellView` は `NSView` なので native focus ring が付く。触らない。

### H3. `tileButton` の当たり判定と状態（AUDIT D4）
- `TerminalTileView.tileButton` を 28×28pt（`contentShape` は維持）に拡大、`.onHover` で `Hum.paper3` の丸背景、`.focusable()` + `humFocusRing`。
- 既存の `.help` / `.accessibilityLabel` は維持。
- タイトルバーの縦パディングを 1〜2pt 詰めて 28pt 化でも高さが伸びすぎないよう調整。

### H4. ペインのフォーカスリングを Hallmark 準拠に（AUDIT D3）
- `TerminalTileView`: `isFocused` 時のリングを `accent.edge` から **`Hum.focusRing`（高コントラスト）** に。太さ 3pt（contrast 時 4pt）。`isMaximized` のリングは従来どおり accent。
- `PaneTreeView`: `focusedID` の初期値を `store.layout?.leaves().first`（起動直後の最初のペインにリング）。
- `focusPane` / `focusSpecificPane` / `focusTile` は既に `.humiFocusChanged` を post しているので追従は OK。クリック経路も OK。**キーボード Tab は SwiftTerm 側が不透明なので対象外**（`⌘⌃矢印` が代替、と `humi.md` に明記）。

### H5. `DividerHandle` の可視性・カーソル・キーボード（AUDIT A1, D5）
- カーソル: `.onHover` の `push/pop` を廃止し、`NSTrackingArea` + `cursorUpdate` を持つ小さな `NSViewRepresentable`（`ResizeCursorArea`）を hit 領域に敷く。View 消滅で自動的にトラッキングエリアも消えるためリークしない。
- 可視: 既定は `Hum.hairline` のまま。hover / ドラッグ中は `Hum.ink2` に太さ 2pt。
- キーボード: 新規 `HumiAction` 2 個 — `growPane`（`⌃⌘]`）/ `shrinkPane`（`⌃⌘[`）。フォーカス中ペインを含む split の、そのペイン側の比率を ±0.03。`SessionStore.nudgePaneRatio(besideLeaf:by:)` を新設（`PaneNode` に `adjustRatio(forLeaf:delta:)` 純粋関数）。5 言語文字列 + defaults + KeymapStore + `handle` 分岐 + `HumiApp.commands`。
- テスト: `adjustRatio(forLeaf:delta:)` のクランプ・ペア和保存。

### H6. `AlertsPane` の a11y（AUDIT D6, D9）
- trash ボタン: `Label` 化 or `.accessibilityLabel(L("alerts.triggers.remove"))` + 28pt。
- `Toggle("", …)` → `.accessibilityLabel(L("alerts.triggers.enabled"))`。
- トリガー `.color` 行: color stepper の隣に色名テキスト（`Hum.accentName(i)`）を出して「色だけ」を避ける。
- 新規文字列 2 個（`alerts.triggers.remove` / `alerts.triggers.enabled`）× 5 言語。

### H7. Increase Contrast / Reduce Transparency（AUDIT D7, D10）
- `Hum.contrastBoost: Bool { NSWorkspace.shared.accessibilityDisplayShouldIncreaseContrast }`。
- `Hum.hairline` を contrast 時 0.10→0.22 相当に、tile の tint 上限を 0.12→0.20 に、focus リング +1pt。
- `Motion.considerate` に Reduce Transparency は無関係なので、`Hum.tileTintOpacity(hovering:)` ヘルパを噛ませて一元化。
- 動的 `NSColor` は appearance クロージャ内で `NSWorkspace` を読めないため、`contrastBoost` は View 側の `@Environment(\.colorSchemeContrast)` で分岐（SwiftUI が increase contrast を `.increased` として渡す）。
- テスト: なし（表示のみ）。目視で確認。

### H8. コントラスト自動試験（AUDIT D8）
- `Tests` に `suite("Contrast")`: `Hum` の主要ペア（ink/paper, ink2/paper, ink/paper2, focusRing/paper, accent.edge/paper …）を light/dark 両方で WCAG コントラスト比計算し、テキスト系は ≥ 4.5、大字/非テキストは ≥ 3.0 をアサート。
- `Hum` に非公開 `luminance(_ hex: UInt32) -> Double` と `contrastRatio(_:_:) ` を testable で公開（`@testable`）。
- 破れているペアが出たら H7 のトークン調整で詰める。
