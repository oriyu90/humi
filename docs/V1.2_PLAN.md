### 1.4 不変条件（壊すと再発バグ）

- 端末 NSView の生成は `TerminalRegistry.controller(for:)` の一点だけ。View 側で作らない。
- グリッドは eager（Lazy 禁止）。スクロールで端末 View を recycle させると描画が止まる。
- `applicationWillTerminate` → `TerminalRegistry.terminateAllSync()`（同期リープ）。非同期に戻すと孤児化。
- **アイドルで回り続けるアニメ/タイマーを足さない**（`repeatForever` / `TimelineView(.animation)`）。
  v1.0.1 で `CharacterMark` の breathing が常時 8〜10% CPU の原因になった。
- `Hum.paper` などのクローム色は動的 `NSColor`（`Hum.dyn(light:dark:)`）。`@MainActor` 計算プロパティに
  しない（`HumButtonStyle` へ isolation が波及する）。
- 新規ユーザー向け文字列は 5 言語すべてに追加。`bash Scripts/test.sh` の `L10n` スイートが
  キー一致・`%`（プレースホルダ）数一致・空値なしを検査する。
- `Package.swift` の `.unsafeFlags(["-enable-testing"])` は無条件。debug 限定に戻すと `swift build` が落ちる。

## 4. A. 分割ペイン / ペインツリー（詳細設計）

### 4.1 ねらい

タイルを「追加順にリフローする 1 列グリッド」から「H/V に自由分割できるペインツリー」へ。
iTerm2 の `⌘D`（縦分割）/ `⌘⇧D`（横分割）相当 + キーでのフォーカス移動 + 分割線ドラッグでの比率変更。

### 4.2 モデル（新規 `Sources/HumiKit/Core/PaneTree.swift`）

```swift
enum Axis: String, Codable, Sendable { case horizontal, vertical }  // horizontal = 左右に並ぶ

indirect enum PaneNode: Codable, Equatable, Sendable {
    case leaf(UUID)                                   // セッション id
    case split(axis: Axis, children: [PaneNode], ratios: [CGFloat])  // ratios.count == children.count, 合計 1
}
```

純粋操作（すべてユニットテスト対象）:

- `leaves() -> [UUID]` — 左→右・上→下の順で葉を列挙。
- `contains(_ id: UUID) -> Bool`
- `insert(besideLeaf id: UUID, axis: Axis, newLeaf: UUID, after: Bool) -> PaneNode`
  — 対象葉と同じ親が同 axis の split ならそこに挿入、違えば対象葉を 2 要素 split に置換。ratios は均等 or 50/50。
- `remove(leaf id: UUID) -> PaneNode?` — 葉を削除。親 split が子 1 個になったら畳む（`.split(_, [x], _) → x`）。
  全部消えたら `nil`。
- `focusNeighbor(of id: UUID, direction: Direction) -> UUID?`
  — 幾何ベース。各葉の矩形を `frames(in: CGRect)` で求め、方向側にあり重なりが最大の葉を返す。
- `swap(_ a: UUID, _ b: UUID) -> PaneNode`
- `setRatio(atSplitContaining id: UUID, dividerIndex: Int, to r: CGFloat) -> PaneNode`（0.05〜0.95 でクランプ）
- `normalized() -> PaneNode` — ratios 合計を 1 に正規化、`split` の children<2 を畳む、`ratios.count` 不整合を補正。
- `frames(in rect: CGRect, gap: CGFloat) -> [UUID: CGRect]` — 描画とフォーカス移動の共通土台。

`Direction { left, right, up, down }`。

### 4.3 `SessionStore` の改造

- `@Published private(set) var layout: PaneNode?` を追加（葉のない状態は `nil` = 空状態）。
- `sessions: [Session]` は「葉レジストリ」として残す（メタデータ置き場）。`layout` が構造の真実。
- `add()` 系:
  - `add(workingDirectory:profileID:)` は従来通り「末尾に葉を足す」= `layout` が `nil` なら `.leaf(id)`、
    あれば「最後の葉の右に horizontal 挿入」で **v1.1 と同じ 1 列リフロー相当** の初期挙動にする。
  - `split(focusedLeaf:axis:profileID:) -> Session` を新設（`⌘D` / `⌘⇧D` から）。新セッションを作り
    `layout = layout.insert(besideLeaf:...)`。
- `close(_ id:)` → `layout = layout?.remove(leaf: id)?.normalized()`。空になったら `nil`。`maximizedID` も掃除。
- `move(id:before:)`（現ドラッグ並べ替え）は当面「葉の swap」に読み替え、もしくは D&D で
  `insert(besideLeaf:)` に置き換える（後述の PaneTreeView での D&D 設計次第）。
- **マイグレーション**: `restore()` で `layout` が JSON になければ、`sessions` の順序から
  「1 列 horizontal split（均等 ratios）」を組む。既存ユーザーの見た目を変えない。
- `persist()` は `{sessions, layout}` を書く。`Persistence.decode` の対象型を
  `struct SessionsFile: Codable { var sessions:[Session]; var layout: PaneNode? }` にする（旧
  `[Session]` トップレベル配列も読めるよう `decode` を 2 段構えに、または `SessionStore.restore` で分岐）。

### 4.4 UI（`SessionGridView` → `Sources/HumiKit/UI/PaneTreeView.swift`）

- 再帰 View。`PaneNode` を `GeometryReader` の矩形に対して割り付ける。
- **分割線は自前の `Divider` + ドラッグハンドル**（`HSplitView`/`VSplitView` は任意ネスト + 比率永続が
  やりづらい）。ハンドルの `DragGesture` → `store.setRatio(...)`。ドラッグ中は 60fps 更新でも可だが、
  端末リサイズが重いので `throttle`（例: 1/30s）を検討。
- 葉は既存の `TerminalTileView` をそのまま描く（`isMaximized` は現状維持: 一時的に全域オーバーレイ）。
- eager 構築（Lazy 禁止）。葉が画面外でも View ツリーに残す。
- フォーカスされている葉に枠ハイライト（現状フォーカスリングが弱い件も一緒に改善）。
- **キー操作**（`HumiAction` に追加、§6 参照）:
  - `splitH` = `⌘D`（左右） / `splitV` = `⌘⇧D`（上下）… ※ iTerm と逆に感じる人向けにラベルは
    「左右に分割 / 上下に分割」で明示。
  - `focusPaneLeft/Right/Up/Down` = `⌘⌥←→↑↓`（現 `nextTile`/`prevTile` は「順送り」として残すか統合）。
  - `swapPane`（任意）、`equalizeSplits`（`⌘⌥=`）。
- `RootView.handle(_:)` に分岐を足す。`focusTile` は `store.layout` の `focusNeighbor` を使う実装に差し替え。

### 4.5 リスクと対策

| リスク | 対策 |
|---|---|
| 端末 NSView の再ホストが分割/リサイズで壊れる | `TerminalEmulatorView` は今も rehost 対応。PaneTreeView も **葉ごとに安定した `.id(sessionID)`**
  を付け、ツリー再構成で葉 View が作り直されないようにする。ネストした `ForEach` の id に注意。 |
| ratios 不整合で NaN / 0 幅 | すべての操作の出口で `normalized()`。`frames(in:)` は最小幅/高さ（例 120pt）を保証。 |
| 旧 `sessions.json` の破損 | マイグレーションはフェイルセーフに（layout デコード失敗 → sessions 順で再構築）。
  破壊的書き込み前に 1 度だけ `sessions.json.bak` を残すのも可。 |
| ⌘Q 時の子プロセス回収 | 変更なし（`terminateAllSync` は葉数に依存しない）。ただしデバッグで「多ペインからの ⌘Q」を再検証。 |
| CPU | 分割線ドラッグ以外でアイドルに回るものを増やさない。ドラッグ中だけ更新。 |

### 4.6 フェーズ分割

1. `PaneTree.swift` + ユニットテスト（insert/remove/focusNeighbor/normalized/frames）。**UI 触らない。**
2. `SessionStore` に `layout` 導入 + マイグレーション + `split/close/swap/setRatio` + 永続化。テスト追加。
3. `PaneTreeView.swift` 実装、`RootView` を差し替え。`SessionGridView.swift` は削除（`GridLayout.swift` の
   列数計算はもう使わないなら一緒に削除、テストも）。
4. `HumiAction` に split/focusPane/equalize を追加（+ 5 言語文字列 + defaults + KeymapStore）。
5. 実機デバッグ（分割・フォーカス移動・リサイズ・close で畳む・maximize・⌘Q・復元）。中間コミット。

## 5. B〜F の設計

### 5-B. ウィンドウ配置（Arrangement）

- `Sources/HumiKit/Core/Arrangement.swift`:
  ```swift
  struct Arrangement: Codable, Identifiable {
      var id: UUID; var name: String
      var windowFrame: CGRect
      var layout: PaneNode
      var leaves: [LeafSpec]   // {sessionUUIDは新規採番, cwd, profileID, title, accentOverride}
  }
  ```
- `ArrangementStore`（`arrangements.json`）。CRUD + `.humiarrangement` I/O。
- 保存: 現在の `store.layout` + 葉ごとの `Session` メタ + `NSWindow.frame` をスナップショット。
  葉 id は保存時に「配置内の相対 id」に振り直す（復元時に新 UUID を採番）。
- 復元: `store.closeAll()` → 各 leaf の `Session` を作り直し（profile 適用）→ `layout` を再構築（id 対応表で
  差し替え）→ `NSWindow` の frame をセット。
- メニュー: 「配置を保存…」「配置を復元 ▸（名前一覧）」。`HumiApp.commands` に追加。
- カバー範囲: 実装可能機能リスト §17「Project 一括起動 / 一括終了 / 復元」。

### 5-C. グローバルホットキー / Quake ウィンドウ

- `Sources/HumiKit/Core/HotKeyCenter.swift`: Carbon `RegisterEventHotKey` のラッパ（`NSEvent` グローバル
  モニタはフォーカス奪取が不安定なので使わない）。`InstallEventHandler` + `EventHotKeyID`。
- `AppSettings`: `globalHotkeyEnabled: Bool` + `globalHotkeyChord`（`KeyChord` を流用、`keymap.json` とは別。
  UserDefaults に `KeyChord` を JSON 文字列で持つ）。設定 UI は `GeneralPane` か新規 `WindowPane`。
- 動作（MVP）: ホットキーで Humi を activate / 最前面 / トグル hide。
- Quake（ドロップダウン）は stretch: 画面上端に貼り付くボーダレスウィンドウ + スライドイン。まず MVP。
- 注意: `RegisterEventHotKey` はアクセシビリティ許可不要（`NSEvent` グローバルモニタと違う）。ただし
  ホットキー衝突時は静かに失敗するので、設定 UI で「登録できたか」を返す。

### 5-D. 通知

- `Sources/HumiKit/Core/NotificationCenter+Humi.swift`（名前衝突回避のため型名は `HumiNotifier`）。
  `UNUserNotificationCenter`。初回利用時に `requestAuthorization`。
- トリガー（正規表現なし。実装可能機能リスト §12）:
  - **長時間プロセス終了**: `TerminalController` が子プロセス開始時刻を記録 → `processTerminated` で
    経過 > N 秒なら通知（N は設定、既定 30s）。バックグラウンドウィンドウ時のみ、等の条件も。
  - **bell 受信**: `HumiTerminalView.bell` をオーバーライド（`bellStyle` の分岐に notify を追加）→ 通知。
  - **エラー文字列一致**: プロファイルごとに「監視文字列」リスト（部分一致）。`HumiTerminalView` の
    フィード側にフックが必要 → SwiftTerm 1.20 に生バイトのフックがあるか要調査。無ければ
    `Terminal` の `feed` を override するサブクラス手段を検討（`AppleTerminalView.feed` は `public`）。
  - **入力待ち**（任意）: 一定時間出力が無い + 子プロセスありで「待機中」通知。
- 通知クリック → 該当ペインをフォーカス（`UNUserNotificationCenterDelegate`, userInfo に sessionID）。
- プロファイル単位の on/off + 音。`Profile` に `notify: NotifyPrefs` を足す（`init(from:)` 更新）。

### 5-E. 正規表現トリガー（iTerm2 の Triggers 相当）

- D の「出力監視フック」が前提。行確定ごとに正規表現マッチ。
- `Trigger { pattern: String, action: TriggerAction }`。`TriggerAction` = `.notify / .sound / .highlightTile /
  .badge(String) / .sendText(String) / .setSessionColor(Int) / .runCommand(String) / .log }`。
- プロファイルに `triggers: [Trigger]`。設定は新規 `TriggersPane`（or ProfilesPane 内）。
- パフォーマンス: マッチは行バッファに対して行うので、`NSRegularExpression` をコンパイル済みでキャッシュ。
  トリガー無効時はフック自体を張らない（アイドルコスト 0）。
